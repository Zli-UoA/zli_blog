## 概要

- Zli の Slack チャンネル (#t_webfront) で持ち上がった読書会企画を、esaでの企画書作成と経費申請を経て公式サポート (書籍代 + 昼食代) 付きのイベントにしました。
- 「事前読書なし・5人限定・1日集中 (60分サイクル) 」のフォーマットにより、脱落者を出さずに全6章を完走しました。
- この前例と学内LTでの共有がきっかけで、「TRPL輪読合宿」や「Three.js勉強会」など次の企画が立ち上がっています。
- 昼食付きの集中輪読会は想像以上に捗りました。

## 1. 企画を公式化するまで

Zli は会津大学の技術系サークルです。サークル内には自由に参加・作成できる Slack チャンネルがあり、その中の #t_webfront で「SOPやCORSなどブラウザのセキュリティモデルを根本から理解したい」という課題感が共有されました。
これを有志の非公式な集まりで終わらせず、サークル公式の支援を取り付けるため、次の手順を踏みました。

まず esa (文書共有ツール) で [企画書](https://esa-pages.io/p/sharing/14287/posts/345/8002b95de2e70c2948aa.html) を作成・共有しました。目的、開催日時、タイムスケジュール、予算 (書籍代・昼食代) を書いています。

次に会計と交渉しました。「1日通して実施する集中型勉強会のため、昼食代の支給が必要」という根拠を提示したところ、書籍代 (1,000円) と昼食代 (上限1,000円/人) の経費支援が認められました。

正規のプロセスを通したのは、「目的と計画がしっかりしていれば、有志の企画でも公式サポートを受けられる」という前例を作りたかったからです。

## 2. 当日のフォーマット

長期間の輪読会では脱落やモチベーション低下が付きものなので、それを防ぐために当日を以下のように設計しました。

- 日時・場所  
2026年7月20日 (月・海の日) 10:00〜16:20 / あいおいΔ
- 参加人数  
密度を保ち全員が議論に参加できるよう5名に限定  
[connpass 募集ページ](https://connpass.com/event/34567/)

進行サイクルは、当初1章あたり60分を3ステップに分けて回す予定でした。

- 20分 読書
- 20分 担当者による解説
- 20分 参加者全員での議論

実際には時間を厳密に区切らず、60分で担当者が解説しながら議論も進める形式に変更しました。

## 3. 技術的な学び

対象書籍の『Origin 解体新書』 (Jxck著) を通じて、ブラウザのセキュリティ構造を低レイヤまで読み解きました。当日の議論で特に印象に残った話を書きます。

### Origin の定義と CORS の理解

まず Origin の定義でスッキリしました。scheme / host / port のタプル、つまり「どのプロトコルで、どのホストに、どのポートへ」アクセスしているか、というシンプルな話です。

CORS の章では、その定義と今まで遭遇してきたエラーがようやく繋がりました。CORS で弾かれるのはリクエスト自体が送られないからではなく、レスポンスを JavaScript から読めるかどうかをブラウザが判断しているから、というのが大きな理解のポイントでした。この概観が頭に入ると、preflight がなぜあるのかや、ブラウザがなぜ CORS を実装しているのかも自然に納得できました。

### 略語多すぎ

Chapter 06 (Site Isolation 関連) では、担当者が次の記述を読み上げた瞬間、全員が「えっ」という顔をしていました。

「あるページが COEP と COOP を指定すれば、そのページに含まれる全てのサブリソースは CORP を必須とし、Opener も COOP が一致するページとしか生成されない」  
—— 『Origin 解体新書』 Chapter 06 より

Site Isolation のような複雑な概念は1日では到底消化しきれず、「分かったつもり」で終わってしまった部分もあります。それでもブラウザの内部構造に踏み込む面白さはしっかり体感できたので、今後も勉強を続けていきたいです。

## 4. その後の展開

すると「自分たちも企画を通してサポートを受けよう」という話になり、現在サークル内で動いている企画はこんな感じです。

「泊まり込みにするなら銭湯代の支援も申請できるのでは」というアイデアから企画化。

- Three.js勉強会  
自然発生的に企画・調整中。
